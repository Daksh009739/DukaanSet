# V15.2 contextual VoiceOS discovery

One `ContextualVoiceOSHero` uses the current route, authorised business state and shared VoiceOS action registry. Main business pages show the standard hero; record details use the compact variation; the approved dashboard integrates a slim strip between its welcome region and metrics. Intelligence headings follow the selected ProfitPilot, reorder, bill-intelligence or simulator tool. Settings, help, public authentication and marketing screens have no hero, and printing hides it.

Every microphone CTA opens the existing business-scoped VoiceOS. Examples prefill its editable command input and wait for explicit Review. They do not parse, create transactions, navigate away or start microphone capture on click. Existing forms remain mounted; explicit commands override page intent. Current customer, product, supplier and invoice references resolve against authorised current-business records, and product references retain their validated ID through stock review. Successive product pages with identical suggested text also compare the current product ID, so a restored draft cannot retain the previously selected product. Frozen retries and existing domain confirmation remain authoritative.

The old stock discovery banner is replaced, with links to detailed voice entry and entry history retained. Collapse is stored in localStorage under the authenticated user ID, survives page/business/language changes and reloads in that browser, and has an accessible reopen control. UI language stays independent of speech recognition language. English, Hindi and Hinglish use central dictionaries. The hero uses CSS Modules, keyboard focus styles, reduced-motion handling and mobile layouts starting at 320px.

Suggested commands are checked against the real shared engine. Small additions support English payment and purchase role phrases, Hindi supplier creation and outstanding queries, and the explicit Hindi spelling of Maggi. Customer names never populate product fields. Bill intelligence continues to support text and text PDFs; image OCR remains unconfigured.

Validation: 255 unit tests, locale parity across 2,296 keys with no hardcoded visible copy, lint, types, the 40-case/134-slot semantic corpus, seven unique browser cases, and a successful production build. The compiled review checks safe product prefill, customer dues, the actual selected invoice preview, unsaved sale preservation, collapse persistence and 36 language/width/page combinations at 1440/768/390/320px with zero hero accessibility violations. Production screenshots were visually inspected for spacing and the preserved sidebar-toggle fix. The full exact-head PR Quality workflow also retains all earlier browser and compiled business checks.

This change introduces no transcription engine, independent action parser, AI render-time calls, database migration, production promotion or claim of live microphone/provider accuracy. Hosted staging still depends on the existing external backend configuration.
