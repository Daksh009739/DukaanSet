# V14 manual and voice capability matrix

Voice and typed commands share `advanceVoice`, `voiceActionRegistry`, entity resolution and authoritative domain services. English, Hindi and Hinglish deterministic parsing and aliases are covered by unit and browser regression suites. This does not establish live acoustic recognition accuracy. Ambiguous names, variants, quantities, payment methods and price bases require review.

“Direct” means an editable conversation draft followed by one Save. “Reviewed workflow” opens the existing domain form with available values prepared; that form performs its final confirmation. Opening a workflow is never reported as a completed business transaction.

| Backup/export, destructive deletion, bulk financial operations | Existing authorised tooling | Explicit manual scope/review | Existing security controls | Automatic voice execution unsupported |
| Unsupported question or ambiguous action | `unknown`; clarification only | Merchant revises instruction | No writes | Helpful scoped fallback; no arbitrary generated database access |

Retries of direct financial writes, stock batches and DemandPulse preparation retain an immutable payload and idempotency key. Profile/price edits use the existing optimistic prior-value snapshot rather than financial idempotency; an uncertain response must be reviewed against the refreshed record. A repeated transcript is never permission to save.

Speech uses an injectable browser adapter with final/interim separation, repeated-index replacement, owner isolation, permission/error feedback, bounded capture and cleanup. Cloud STT and generative AI are not configured or claimed. Microphone tests use controlled browser recognition events; a human speaking into a real supported microphone remains an external acceptance check.
